# 模块化叠加与自动编号机制详解（Rmd 撰写习惯对照版）

> 面向：写过 Rmd 报告的分析师。目标：讲清 reporter 如何把"跑完一层出一个章节、最后自动叠成一份报告"做成全自动——包括 Figure/Table 序号的连续编排与侧栏 TOC 的自动规划。

## 1. 两种撰写过程的逐步对照

| 步骤 | 旧 Rmd 流程 | reporter 流程 |
|---|---|---|
| 建报告环境 | `Report.R` 把参数塞进 `globalenv()` | `ctx <- report_context(...)`，参数都在 `ctx$meta` |
| 写一个章节 | 写一个 child Rmd（或在 1173 行大文件里写一节） | 写一个 `module(id, title, render=function(ctx) tagList())` |
| 插一张图 | `include_graphics()` + 手写 `fignum=fignum+1` + 图注 | `ctx$figure(path, title)` —— 自动 base64 + "Figure N" + 灯箱 |
| 插一张表 | 手写 `tablenum=tablenum+1` + reactable/kable | `ctx$data_table(dt, title)` —— 自动 "Table N" + 搜索/分页 |
| 层级小节 | `## 标题`（TOC 依赖 rmdformats） | `ctx$subsection("小节")` —— 自动进侧栏 TOC |
| 章节拼接 | `loadRmd2(child1, child2, child3)` 按 `dir.exists()` 手工挑 | `add_module()` 注册一次，`required_dirs` 门控声明一次永久生效 |
| 编号连续性 | **全局计数器 + 拼接顺序敏感**（child 增删须手动重排计数） | 计数器在 ctx 内，**按当次渲染实际顺序自动连续** |
| 渲染 | `rmarkdown::render()`，一处报错全文中断 | `render_report()`，单模块失败→占位+继续 |
| 改结构 | 改 Rmd 正文 | 改 module 列表顺序（或 spec YAML 的 layers 顺序） |

**核心差异**：Rmd 的编号/TOC 依赖"文本拼接顺序"，reporter 依赖"模块渲染时的实际产出"——模块少一层，编号与目录自动少一段；多一层自动多一段，**永不错位**。

## 2. 自动叠加的源码级机制（四个环节）

### 2.1 渲染主循环（`R/report.R` render_report）

```r
for (mod in report$modules) {
  reason <- rp_module_skip_reason(mod, ctx)      # ① 门控判定
  if (!is.na(reason)) { skipped <- ...; next }   # 不满足→跳过
  ctx$.rp_set_module(paste0("mod-", mod$id))     # ② 记录当前模块归属
  content <- tryCatch(mod$render(ctx), error=..) # ③ 隔离渲染
  rendered[[...]] <- list(id=, title=, content=) # ④ 按序收集
}
```

- ① `rp_module_skip_reason()`：检查 `required_dirs` 是否都存在于 `result_path`（如 `QC`、`Map`），再执行可选的 `when(ctx)` 谓词（如 `type=="1"` 才出的差异层）。**只跑完 QC 和 Map 时，后 9 层目录不存在 → 自动全部跳过，报告只剩两层**。
- ④ `rendered` 列表顺序 = `add_module()` 注册顺序 = 页面章节顺序 = **TOC 与导航栏顺序**。

### 2.2 编号器（`R/context.R`）——序号自动连续的来源

```r
next_fig <- function() { private$fig <- private$fig + 1L; private$fig }
next_tbl <- function() { private$tbl <- private$tbl + 1L; private$tbl }
```

- 计数器是 **ctx 私有环境里的闭包变量**，不是全局变量。
- 任何模块调用 `ctx$figure()` / `ctx$data_table()` 时自增取号——**编号 = 当次渲染中图/表实际出现的先后顺序**，跨模块天然连续。
- 例：QC 层 2 表 3 图，Mapping 层 2 表 1 图 → Table 1-2（QC）→ Table 3-4（Mapping）；Figure 1-3（QC）→ Figure 4（Mapping）。**没有任何模块需要知道自己的编号**。
- 跳过的模块不产生内容 → 不占号 → 补跑新层后重渲，新层编号自动出现在正确位置（编号始终等于"本次出现的顺序"）。

### 2.3 TOC 注册（侧栏目录自动规划）

```r
ctx$subsection("基因组区域分布")   # 模块内一行
```

- 内部向 `ctx$.rp_toc_entries()` 注册 `(module, id, title, level=3)`，id 由标题 slug+哈希自动生成（防中文/重名冲突）。
- 装配阶段取出全部 entries，**按 rendered 模块顺序分组** → 侧栏两级目录（模块级 + 小节级）。
- 前端 `IntersectionObserver`（`reporter.js`）滚动同步高亮——TOC 是渲染的副产品，不是手写的。

### 2.4 导航栏与门控列表

- 导航栏菜单 = rendered 模块列表直接映射（同 TOC 顺序）。
- 被 `$skipped` 的模块不出现在页面任何地方；`res$skipped` 留有原因（如 "missing directories: 5.DiffPeaks"）；`res$errors` 是失败模块（页面内为红色占位块，**不中断其他模块**）。

## 3. 可复现示例：QC + Map 两层叠加

```r
library(reporter)
REAL <- "/path/to/atac/results"   # 你的结果目录（本示例需已跑完 QC 与 Map）

ctx <- report_context(REAL, species = "Drosophila", type = "1")

mod_qc <- module("qc", "测序数据质控（QC）", required_dirs = "QC",
  render = function(ctx) {
    dt <- read_result_table(file.path(ctx$meta$result_path,
      "QC/Summary/Filtered.Summary.txt"))
    tagList(
      ctx$subsection("质控统计"),
      ctx$data_table(dt, title = "数据质控信息汇总表"),     # ← Table 1
      ctx$figure(file.path(ctx$meta$result_path,
        "QC/Summary/Plot/IP1.Quality.png"), title = "碱基质量分布")  # ← Figure 1
    )
  })

mod_map <- module("map", "比对分析（Mapping）", required_dirs = "Map",
  render = function(ctx) {
    dt <- read_result_table(file.path(ctx$meta$result_path,
      "Map/Summary/mapping.stats.txt"))
    tagList(
      ctx$subsection("比对统计"),
      ctx$data_table(dt, title = "reads比对统计"),          # ← Table 2
      ctx$figure(file.path(ctx$meta$result_path,
        "Map/Summary/A-1.png"), title = "比对深度分布")      # ← Figure 2
    )
  })

report <- create_report(ctx) |>
  add_module(mod_qc, mod_map, mod_references())   # 叠加：注册即完成规划
res <- render_report(report, output = "qc_map.html",
  theme = reporter_theme(preset = "blank", style = "v2"))
res$modules    # "mod-qc" "mod-map" "mod-references"
res$skipped    # 后续层因目录缺失自动跳过（附原因）
```

产出：一个 HTML——TOC 两层、Table 1/2、Figure 1/2 连续编号、导航栏自动两项 + 参考文献。**稍后补跑 Peak 层，只改一处：`add_module(mod_peak())`**，重渲后它作为 Table 3 / Figure 3 自动接在后面，TOC/导航同步出现。

## 4. 场景推演（为什么"最后自动叠加成一个"天然成立）

| 场景 | 行为 |
|---|---|
| 只跑完 QC+Map | `required_dirs` 门控 → 其余层 skip，报告 = 2 层 + references；编号从 1 连续 |
| 跑完 Peak 后重渲 | 同一份代码重新 render，第 3 层自动渲染，编号接续前两层 |
| type=0（单分组） | `when()` 谓词让 diff/enrich/motif 层自动跳过（与目录门控叠加生效） |
| 层顺序调整 | 改 `add_module()` 顺序即可，编号/TOC/导航全部随渲染顺序自动重排 |
| 某层渲染报错 | 该层位置留下红色错误占位，其余层照常（`res$errors` 可查） |
| 声明式方式 | `atac_spec.yaml` 的 `layers:` 顺序即叠加顺序，编译后走完全相同的机制 |

## 5. FAQ

**Q：为什么我的编号从 Figure 9 开始？**
A：ctx 被复用了。计数器在 ctx 里，一份报告必须新建一次 `report_context()`（见 `inst/templates/make_example_report.R` 的 `new_ctx()` 写法）。

**Q：想让某个元素不占编号？**
A：直接用原语而非 ctx 方法——`table_block(dt)`（无号）/ `figure_block(path)`（无号）。ctx 方法总是编号。

**Q：两个模块想交换顺序？**
A：交换 `add_module()` 调用顺序即可；或 spec 里交换 `layers:` 顺序。TOC/导航/编号自动跟随。

**Q：调试某一层？**
A：`render_report(report, only = c("qc"))` 只渲染该层（其余不渲染、不编号、不出现在 TOC）。

**Q：QC 和 Map 是两次不同运行的结果目录怎么办？**
A：`report_context()` 只收一个 `result_path`。把两次输出放到同一父目录的不同子目录，让各模块的 `required_dirs` / `ctx$find(dir=)` 指向各自子目录即可——叠加的是"层"，不是"目录"。

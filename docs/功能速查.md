## 0. 一页总览：最小可用模板

```r
library(reporter)

ctx <- report_context(result_path, species = "Homo_sapiens",
                      project = "项目名", code = "编号",
                      logo = "smzy", type = "1")
report <- do.call(add_module, c(list(report = create_report(ctx)),
                                chip_report_modules()))
res <- render_report(report, output = "report.html",
                     theme = reporter_theme(preset = "smzy", style = "v2"))
res$errors   # 失败模块清单（渲染不中断）
```

调用链：`report_context()` 建 ctx → `module()` 定义章节 → `create_report()/add_module()` 组装 → `render_report()` 门控+隔离渲染+编号+装配 → `save_html()` → `inline_html()` 单文件落盘。

## 1. 渲染主线（5 个核心 API）

### 1.1 `report_context()` —— 报告上下文（唯一状态载体）

```r
report_context(result_path, species = NA_character_, project = NA_character_,
               code = NA_character_, company = "", phonenum = "", logo = "blank",
               type = "1", caption_lang = c("en", "zh"), explain_file = NULL,
               options = list())
```

| 参数 | 说明 |
|---|---|
| `result_path` | 结果目录（必须存在，否则报错） |
| `species` | 物种名（供 `load_genome_version()` 与封面展示） |
| `project` / `code` | 项目名 / 项目编号（导航栏、封面、页脚） |
| `company` / `phonenum` | 公司与电话（覆盖品牌预设值） |
| `logo` | 品牌关键字 `smzy/jinyu/blank`（由主题解析成 logo 文件） |
| `type` | 业务分支：`"1"` 有重复/差异组，`"0"` 单分组（模块 `when()` 用） |
| `caption_lang` | 图表编号语言：`"en"` Figure/Table（默认），`"zh"` 图/表 |
| `explain_file` | 自定义表格解释 xlsx；NULL 用包内置 TableExplain.xlsx |
| `options` | 命名 list，流程自定义参数，存入 `ctx$meta$options` |

**底层逻辑**：返回一个 `reporter_ctx` 环境对象（环境=引用语义，所有模块共享同一状态）。内含：`meta`（上述参数）、图/表计数器（私有环境，与模块顺序解耦）、TOC 注册表（`subsection()` 写入）、**列解释注册表**（`load_explanations()` 惰性加载并缓存，首次 `data_table()/explain()` 才读 xlsx）。

### 1.2 `module()` —— 定义一个报告章节

```r
module(id, title, render, required_dirs = character(0), when = NULL)
```

| 参数 | 说明 |
|---|---|
| `id` | 锚点 id（页面锚 `#mod-<id>`、TOC、导航栏引用） |
| `title` | 章节标题（导航栏菜单 + 侧栏目录一级条目） |
| `render` | `function(ctx) -> tagList`。**签名固定**；返回 NULL 等价空 tagList |
| `required_dirs` | 字符向量：相对 `result_path` 的子目录，**全部存在才渲染**（否则记入 `$skipped` 并附原因）——按结果目录自动启停的机制 |
| `when` | `function(ctx) -> logical` 额外开关（如 `type=="1"` 才出的差异分析） |

**底层逻辑**：`render_report()` 对每个模块先查 `required_dirs`（`dir.exists`）与 `when()`，不满足 → skip；满足 → `tryCatch(render(ctx))`，失败 → 报告内 danger 错误占位 + 记入 `$errors`，**不中断整份报告**。

### 1.3 `create_report()` / 1.4 `add_module()`

```r
create_report(ctx)          # 包一个 list(ctx=, modules=list())
add_module(report, ...)     # 追加 1..n 个 module 对象，返回修改后的 report（不可变更新）
```

`add_module` 支持管道；**注意返回值必须接住**（list 拷贝语义，无原地副作用）：

```r
report <- create_report(ctx) |> add_module(mod_a(), mod_b())
# 或： report <- do.call(add_module, c(list(report=report), chip_report_modules()))
```

### 1.5 `render_report()` —— 渲染入口

```r
render_report(report, output = "report.html", theme = NULL, standalone = TRUE,
              title = NULL, only = NULL, quiet = FALSE)
```

| 参数 | 说明 |
|---|---|
| `output` | 输出 HTML 路径 |
| `theme` | `reporter_theme()` 对象；NULL 用 `reporter_theme(preset="blank")` 默认 |
| `standalone` | `TRUE` 单文件自包含（默认）；`FALSE` 输出 HTML+`report_assets/` 目录（数百图大报告更快） |
| `title` | 报告标题（同时进 `<title>`、导航栏、封面） |
| `only` | 字符向量：只渲染这些模块 id —— **调试单模块的快捷通道** |
| `quiet` | 静默进度消息 |

**返回值** `reporter_render`：`$output`（落盘路径）、`$errors`（失败模块 list：id/message）、`$skipped`（跳过模块+原因）、`$modules`、`$counters`、`$size`。

**底层渲染管线**：模块渲染 → TOC 分组 → `rp_page()` 装配（head 依赖+导航栏+侧栏+封面+章节+页脚）→ `htmltools::save_html(libdir="lib")` → `inline_html()` 把 `<script src>/<link href>` 全部内联（图片在 `figure()` 时已 base64；CSS 内 url 再编码；JS 的 `</` 转义防提前闭合）→ **无外链校验**（残留 `lib/` 引用即 warning）→ 单文件落盘。

## 2. ctx 方法族（模块内使用）

| 方法 | 签名要点 | 作用 / 底层逻辑 |
|---|---|---|
| `ctx$subsection(title, desc, id)` | id 自动生成（slug+hash 防中文/重名） | 三级标题；**写入 TOC 注册表**→侧栏目录+滚动同步高亮 |
| `ctx$figure(path, title, ...)` | 见 `figure_block()`，自动传 number | **读图片文件 → `xfun::base64_uri()` 内联**（O(n) 一次读盘）→ 自增图号 → "Figure N" 图注 |
| `ctx$gallery(images, title, ...)` | 见 `gallery()` | 多图画廊（pane 切换/样本搜索/灯箱），图片同样 base64 |
| `ctx$data_table(data, title, ..., explain = TRUE, explain_sheet = NULL)` | 见 `table_block()`+`data_table()` | reactable 表 + 自增表号；**自动挂载列解释**（详见 §5） |
| `ctx$find(pattern, dir, key, strict, gap, recursive)` | 见 `auto_find()` | 结果目录扫描的 ctx 快捷方式 |
| `ctx$explain(cols, sheet)` | 返回 data.frame(表格列名/解释) | 手动查列解释注册表 |
| `ctx$note/warning/tip(...)` | 同 `callout()` | 语义提示框 |
| `ctx$meta` | list | `result_path/species/project/code/type/options/...`，模块**只准从这里取参** |

### 3.1 `read_result_table()` —— 万能表格读取（核心，委托 OXM）

```r
read_result_table(file, sep = NULL, header = TRUE,
                  excel = grepl("\\.(xlsx|xls)$", file, ignore.case = TRUE),
                  nrows = Inf, new_names = NULL)
```

| 参数 | 说明 |
|---|---|
| `file` | 表格路径（csv/tsv/txt/xlsx/xls/**.gz 均支持**） |
| `sep` | 文本表分隔符；**NULL（默认）自动探测**（fread） |
| `header` | 首行是否表头 |
| `excel` | 默认按扩展名自动判定 |
| `nrows` | 只读前 n 行（大 peakAnnotation.csv 配合 `show_number` 用） |
| `new_names` | 字符向量重命名列（长度须等于列数） |

**底层逻辑（分工）**：
- **xlsx/xls → `OXM::readFile()`**（引入 OXM 依赖，统一 Excel 读取；显式 `sheet=1` 规避其自引用缺省）。已知 OXM 命名空间在部分宿主会话（如 testthat）下加载失败（S3method 注册问题，上游 bug）——**失败时无感降级 `openxlsx::read.xlsx`**，读取永不因 OXM 状态中断；
- **文本表（csv/tsv/txt/gz）→ `data.table::fread`** 分隔符自动探测；
- 失败返回 `NULL` 并告警（**不抛错**，模块据此降级为 `empty_block()`）。

### 3.2 `auto_find()` / `ctx$find()` —— 结果目录扫描

```r
auto_find(search_path, format_str = ".rds", gap = "\\.", in_base = TRUE,
          in_dirname = FALSE, key = "xxx", recursive = TRUE, strict = FALSE)
# ctx$find(pattern, dir = NULL, key = "xxx", strict = FALSE, gap = "\\.",
#          recursive = TRUE)   # dir 相对 result_path；NULL=整个结果目录
```

| 参数 | 说明 |
|---|---|
| `format_str` | 扩展名如 `".png"`（自动前后加通配） |
| `key` | 关键字过滤；`strict=TRUE` 时锚定开头（`^key`） |
| `gap` | 样本名分隔符（正则，默认 `\\.`）：取文件名（或目录名）第一段当样本名 |
| `in_base` / `in_dirname` | 样本名取自文件名 / 文件所在目录名（如 `IP1/xxx.png`） |
| `recursive` | 是否递归子目录 |

**返回**：命名 list（样本名 → 文件路径），**空文件自动剔除**，无命中返回空 list 并提示。迁移自旧 `AutoFind`。

## 5. 表格解释系统（自动挂载）

```r
load_explanations(xlsx = NULL)      # NULL=包内置 inst/extdata/TableExplain.xlsx
explain_table(cols, registry = load_explanations(), sheet = NULL)
table_explain(sheet, colns = NULL, excel_file = <内置>, show_text = "点击查看表格解释：")
```

**工作方式**：

1. `load_explanations()` 读全部 sheet（22 个：QC/MapState/ReadsAnno/Peak/DEG/GO/KEGG/HOMER...）→ 注册表：列名 → (sheet, 解释) **多义保留**。
2. `ctx$data_table()` 渲染后自动查表：
   - 列在注册表中**只有一种解释** → 自动附加折叠解释块；
   - 列**多义**（如 `TotalReads` 在 QC=原始 reads、MapState=Clean reads）→ 自动模式跳过，需模块传 `explain_sheet = "MapState"` 钉定；
   - `explain = FALSE` 整体关闭。
3. `report_context(explain_file = "项目自有.xlsx")` 换成项目级解释表（格式同：每 sheet 两列，表头 `表格列名`/`对应含义/解释`）。
4. `table_explain(sheet, colns)` 保留作手动兜底。

## 8. 主题系统

```r
reporter_theme(preset = c("smzy", "jinyu", "blank", "default"), primary = NULL,
               style = c("classic", "v2", "card"), bslib_preset = "flatly",
               base_font = NULL, heading_font = NULL, company = NULL,
               phonenum = NULL, logo_file = NULL, caption_lang = c("en", "zh"),
               footer_note = NULL, extra_variables = list())
```

| 参数 | 说明 |
|---|---|
| `preset` | 品牌预设：主色+logo+公司+电话（smzy=#0D6E8C、jinyu=#B0842A、blank=白标、default=中性蓝） |
| `primary` | 覆盖主色（自动派生 dark/light 变体） |
| `style` | **视觉风格**：`classic`（卡片化+渐变封面，默认）/ `v2`（编辑排版风：细规则线、纯文本编号、880px 列宽）/ `card`（Illumina-DRAGEN 风：浅灰页底、每模块一张白卡片、Inter 字体栈、暖灰文字 #5B575B、细横线表格） |
| `bslib_preset` | 透传 `bs_theme(preset=)`（bootswatch 主题；会附带网络字体增大体积） |
| `base_font/heading_font` | 字体（离线服务器保持默认系统栈） |
| `caption_lang` | 同 ctx，主题值优先注入 |
| `footer_note` | 页脚免责声明 |
| `extra_variables` | 命名 list 附加 CSS 变量（如 `"rp-primary" = "#2B6CB0"`） |

**底层**：全部变量（含 `--rp-*` 自定义）直接传 `bslib::bs_theme()` 编译（bslib 0.12 的 update/add_variables 已废弃）；皮肤 = `body.rp-style-v2` 作用域 CSS 覆盖；`inst/assets/reporter.css` 变量全暴露，一份 CSS 可整体换肤。

## 9. 命令行（流水线入口）

```bash
Rscript inst/templates/run_report.R \
  --result /path/to/results --species Homo_sapiens \
  --project "项目名" --code 编号 --type 1 \
  --logo smzy --company "公司" --phonenum "电话" \
  --modules chip --outhtml report --style v2 --title "报告标题"
```

| CLI 参数 | 对应 R 参数 |
|---|---|
| `--result` | `report_context(result_path)` |
| `--species/--project/--code` | 同名 |
| `--type` | `type`（1=有差异组 0=单分组） |
| `--logo/--company/--phonenum` | `reporter_theme(preset=, company=, phonenum=)` |
| `--modules` | 模块集开关（chip；m6a 预留） |
| `--style` | `reporter_theme(style=)` |
| `--outhtml` | `render_report(output)` |

**退出码**：`0` 全部成功 ｜ `1` 有模块渲染失败 ｜ `2` 参数/环境错误（修复旧 Report.R 吞错返回成功）。R API 层入口：`report_cli(args = commandArgs(trailingOnly = TRUE), do_quit = TRUE)`。

## 11. 空输入语义（防御式约定）

所有面向模块作者/流水线的入口对"空"输入的统一行为——**降级为占位或跳过，绝不抛深层次错误**：

| 输入 | 行为 |
|---|---|
| `read_result_table(NULL/NA/"")` | 返回 `NULL` + message（模块据此渲染 `empty_block`） |
| `auto_find(NULL/NA/路径不存在)` | 空 list + warning |
| `ctx$data_table(NULL/0行 df)` | 渲染 `empty_block("…无数据")`，**不消耗表号**（不留编号空洞） |
| `ctx$figure(NA/路径不存在)` | 透明占位图（`missing_ok=FALSE` 时才报错） |
| `ctx$gallery(list 中含 NULL/NA 项)` | 剔除空项后渲染；全空 → `empty_block` |
| `table_block/kv_table` 空数据 | 表头 + "无数据"占位行 |
| `callout()/text_block()` 全空参数 | 渲染为空（不输出空壳标签），NA 不再变成字符串 "NA" |
| `details_block(NULL)` | 不渲染折叠块 |
| `kpi(NA, NA)` | 值/标签显示 "–"（等宽 dash），永不出现 "NA" |
| `read_bib(NULL/NA/缺失)` | 返回 `NULL` + message（`mod_references` 自动作占位） |
| `render_report(report=NULL)` | 明确报错指向 `create_report()`；`only` 未命中时报可用模块清单 |

实现工具：`rp_is_empty()` / `rp_char1()` / `rp_df_usable()`（`R/utils.R` 内部）。

## 12. 陷阱与 FAQ

| 问题 | 答案 |
|---|---|
| 图片没显示/体积大 | 图片在 `figure()` 时即 base64；数百张大图建议 `standalone=FALSE` |
| 表格解释没出现 | 该表列名在注册表无匹配或多义——传 `explain_sheet=` 或检查 explain_file |
| 模块整章消失 | `required_dirs` 目录不存在（看 `$skipped` 原因），属正常门控 |
| 编号从中间开始 | ctx 被跨报告复用——每份报告必须新建 `report_context()` |
| reactable 表格空白 | 检查数据框是否全 NA/0 行；空数据应走 `empty_block()` |
| bootswatch 皮肤体积暴增 | preset 附带 Google 字体被内联；离线交付用默认 preset |

## 15. 机器可读层（LLM/流水线就绪）

`render_report()` 现在自动在 HTML head 内嵌一份**结构化索引**：

```html
<script id="rp-schema" type="application/json" class="rp-schema">{ ... }</script>
```

### 内容边界（硬约束）

| 进 Schema | 不进 Schema |
|---|---|
| meta（标题/项目/物种/参考版本/引擎/时间戳） | 表格单元格数据 |
| 模块清单（id/标题/顺序） | 图片像素（base64） |
| 图：编号/标题/**来源文件路径**/张数 | 解释与方法学长文 |
| 表：编号/标题/来源路径/列名/行数/列解释映射 | |
| 被引文献（key/编号/DOI） | |

实测体积：chip 演示全报告 1.37MB 中 schema 仅 **4.2KB（0.3%）**，对打开速度零影响（浏览器不主动解析 `type="application/json"`）。

### 消费方式

```r
# 浏览器/LLM 从 HTML 提取
json <- rvest::html_element(read_html("report.html"), "#rp-schema") |> rvest::html_text()
# 流水线直接读 sidecar
render_report(report, output = "report.html", json_sidecar = TRUE)
# → 生成 report.json（与 HTML 并排，pretty 格式）
```

### DOM 锚点

图/表包装元素带 `data-rp-fig="rp-fig-N"` / `data-rp-tbl="rp-tbl-N"` / `data-rp-module="mod-xxx"` / `data-rp-files="路径1|路径2"` 属性，供 LLM 从 HTML 精确定位元素。

### 表格来源登记

`ctx$data_table(..., source = "1.QC/Raw.Reads.txt")`（可传向量）——来源路径进入 schema；未传则该表 `sources` 为空数组。schema 体积上限有单测守卫（< 64KB）。

## 16. 双渲染引擎（P1）

`engine` 配置项控制表格渲染路径，**模块代码零改动**：

```r
render_report(report, output = "report.html", engine = "lite")   # R 参数
# spec YAML 顶层：engine: lite
# CLI：Rscript run_report.R --engine lite ...
```

| 引擎 | 表格实现 | 依赖 | 适用 |
|---|---|---|---|
| `reactable`（默认） | reactable widget（搜索/分页/列宽全部内置） | bslib + reactable 运行时（约 620KB） | 生产默认，交互最强 |
| `lite` | 原生 `<table class="rp-table">` + `reporter-lite.js` 增强 | 零第三方运行时（JS < 5KB） | 大批量交付、弱网环境、规避 widget 兼容问题 |

- lite 网格能力：关键词搜索、点击表头排序（数值自动识别、含千分位）、CSV 导出（带 BOM，Excel 直开）、行数统计
- lite 超过 500 行自动截断并注明（完整数据在交付文件中）；`table_lite_block(max_rows =)` 可调
- 解释下拉在 lite 引擎下同步使用原生表格
- schema 的 `meta.engine` 字段如实记录当前引擎
- 优先级：CLI `--engine` > spec YAML `engine:` > `render_report(engine=)` > 默认 `reactable`

## 17. PDF 导出（P3）

```r
res <- render_report(report, output = "report.html")   # 交互版照常
export_pdf(report, output = "report.pdf")              # 一行导出 PDF
```

- **print mode**：`export_pdf()` 内部以 `print_mode = TRUE` 重渲打印版 HTML——reactable 全量行（`pagination = FALSE`）、解释 `<details>` 强制展开、打印 CSS 强制保留色块
- **Chrome 定位顺序**：`REPORTER_CHROME` 环境变量 → playwright 缓存 → `pagedown::find_chrome()` → PATH 上的 google-chrome/chromium；候选都会跑一次 `--version` 验证（防坏 wrapper）
- 找到 Chrome：`pagedown::chrome_print()`（装了 pagedown）或裸 `--headless --print-to-pdf` 命令
- **找不到 Chrome**：打印版 HTML 保留在磁盘并给出 Ctrl+P 手动导出指引（零依赖兜底）
- 打印样式（`@media print`）：`print-color-adjust: exact`（保留热图/KPI 色块）、A4 `@page` 边距、隐藏导航/侧栏/分页控件、画廊全 pane 平铺、图/KPI/提示框防跨页截断、**长表跨页自动重复表头**
- 交互版 HTML 交付完全不受影响

## 18. 页面端「导出 PDF」按钮（P3 补充）

顶栏右侧新增**「导出 PDF」按钮**（所有皮肤）：点击自动展开全部折叠解释块 → 弹出浏览器打印对话框 → 另存为 PDF；打印结束自动恢复折叠状态（`beforeprint/afterprint` 钩子）。

配套产物：`render_report(..., print_html = TRUE)` 会在 HTML 旁额外生成 **`*_print.html` 打印版**（reactable 全量行、画廊平铺、A4 版式）——大表报告建议开启，用户从按钮打开打印版后 Ctrl+P 即得完整 PDF；`export_pdf()` 也自动产出该配套文件。

**渲染状态重置**：`ctx$.rp_reset_render_state()` 在每次渲染前自动执行——同一 ctx 连续渲染（交互版 + 打印版）时编号/TOC/Schema 完全一致，不再累积。

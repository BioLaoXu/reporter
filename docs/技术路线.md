## 1. 背景与问题定义

公司生信标准分析报告长期基于 R Markdown 手工撰写（`/data/pipeline/m6A/Report`、`/data/pipeline/ChIP/Report2`）。随着流程数量增长，维护成本急剧上升。2026-10 调研实测确认的痛点：

| # | 痛点 | 实测证据 | 直接后果 |
|---|---|---|---|
| 1 | 巨型单文件 Rmd | `m6A.Rmd` 1173 行 / 76KB，无任何 child 拆分 | 改一处动全身，无法单独调试某章节 |
| 2 | 整份复制式"模块化" | ChIP 13 份、m6A 9 份按日期/物种/分支复制的 Rmd 变体 | bug 修复需同步 N 份文件，漂移不可避免 |
| 3 | 全局计数器 | `tablenum/fignum` 靠 Rmd 内 `` `r tablenum=tablenum+1` `` 自增 | child 顺序一变全文编号错乱（main.Rmd 注释已自认） |
| 4 | 全局变量传参 | Report.R 把 10+ 参数写入 `globalenv()`，Rmd 直接取 | 模块无法独立运行/测试， IDE 无法静态检查 |
| 5 | 工具函数漂移 | `utils.R` 存在 5 份副本（utils.bk / utils.v20251203 / utils_RNA / utils_m6A …） | 同名函数行为不一致，改错副本无告警 |
| 6 | 失败被吞 | m6A `Report.R` tryCatch 只 print 不退出 | 渲染失败仍返回成功，流水线无感知 |
| 7 | 调试体验差 | knit 单环境顺序执行，报错定位到行也难复现上下文 | 排查一个图的问题需整份重跑 |

**结论**：问题不在"写不好 Rmd"，而在**缺少一个模块契约与渲染框架**。需要的是：模块可独立开发/测试、结果目录驱动自动装配、单文件交付、页面结构可配置的**报告引擎**。

## 2. 技术选型对比

候选方案四条路线，六维评估（1-5 分，5 最优）：

| 维度 | ① Rmd+bookdown 优化 | ② Quarto (.qmd) | ③ R 出 JSON + Node 渲染 | ④ 纯 R 自建（选定） |
|---|---|---|---|---|
| 模块化 | 2（child 文档 + globalenv，仍弱） | 5（include/profiles/交叉引用） | 4（模板/数据彻底分离） | 4（模块=函数，天然可单测） |
| 外部依赖 | 5（零新增） | 2（需 150MB Quarto CLI，服务器未装） | 1（流水线需维护 Node 环境） | 5（零新增，装包即用） |
| 调试性 | 2（单环境顺序 knit） | 3（freeze/缓存，但仍是文档驱动） | 3（JS/R 两层，跨语言排查） | 5（testthat 直接断言模块输出） |
| 交付形态 | 4（self_contained 成熟） | 5（embed-resources 原生） | 5（--scan 扫图 + 单文件） | 4（自研内联，已验证无外链） |
| 迁移成本 | 4（渐改现有 Rmd） | 3（需装 CLI + 全员学 .qmd） | 2（业务逻辑需重写为 JSON 产出） | 3（utils.R 可收编，Rmd 逐节重写） |
| 维护风险 | 4（成熟但天花板低） | 4（Posit 主推，但外部二进制升级不可控） | 2（依赖第三方小众引擎） | 4（代码全部自有，框架演进自主） |
| **合计** | 21 | 22 | 20 | **25** |

### 2.1 关键调研结论

- **seqyuan/rst 不是 R 包**：实为纯 TypeScript 的 reStructuredText 渲染引擎（npm `@seqyuan/rst-renderer` / `rst-cli`，v0.1.2、22 commits，生态极小），主打「模板 + JSON 数据 → 报告」、`--scan` 通配符扫图、`-s` 单文件交付。其**理念**非常契合本需求，但技术栈要求流水线常驻 Node 运行时，与"装包即用"冲突 → **排除，吸收三个理念**：①模板/数据分离；②结果目录扫描自动发现图片/表格；③单文件自包含交付。
- **Quarto**：模块化与交叉引用最强（原生图/表自动编号、`_quarto.yml` 配 navbar/sidebar、SCSS 主题、profiles 条件渲染），但服务器无 CLI、引入 150MB 非 R 二进制、团队需切换工具链 → **排除，借鉴其"参数注入 + 模块=文件"思路**。
- **Rmd 继续优化**：无法根治 globalenv 传参与单环境调试两大结构性问题 → **排除**。
- **纯 R 自建**：htmltools + bslib（Bootstrap 5 + sass 变量）+ reactable 均为服务器已装成熟包；模块=函数可被 testthat 直接断言；渲染路径不依赖 pandoc（base64/内联自研）→ **选定**。

## 3. 总体架构与渲染管线

详细分层与数据流见两张交互图（内置主题切换与 PNG/SVG 导出）：

- **架构图** [reporter-architecture.html](reporter-architecture.html)：分析流水线 → CLI → Report API（create_report/add_module）→ Context（meta/编号器/TOC 注册表）+ Modules（`function(ctx) -> tagList`）+ Primitives（figure/table/gallery/callout）→ Page Skeleton（navbar/TOC/footer）+ Theme（bslib + `--rp-*`）→ Inline Engine → 单文件 HTML。
- **数据流图** [reporter-dataflow.html](reporter-dataflow.html)：结果目录（0.SampleInfo…5.DiffPeaks）→ Discovery（auto_find / read_result_table）→ Modules（ctx 编号）→ Assembly（含 per-module tryCatch 错误占位）→ Delivery（inline_html 校验后单文件落盘）。

### 3.1 核心机制摘要

| 机制 | 设计 |
|---|---|
| 模块契约 | `module(id, title, render, required_dirs, when)`；`required_dirs` 按结果子目录存在性自动启用（取代 22 份复制变体）；`when(ctx)` 处理 type=0/1 等业务分支 |
| 上下文 | `report_context()` 唯一状态载体；模块禁读全局变量；`ctx$find()` 继承 AutoFind 结果目录扫描 |
| 自动编号 | fig/tbl 计数器在 ctx 内，与模块顺序解耦；`caption_lang` 支持 Figure/Table（默认，交付图表英文约定）或 图/表 |
| 错误语义 | 模块 tryCatch 降级为报告内错误占位；全部失败才终止；CLI 退出码 0/1/2（修复旧吞错缺陷） |
| 单文件内联 | 图片生成时即 base64（O(n) 一次读盘）；`save_html(libdir)` → `inline_html()` fold-in 全部 CSS/JS/字体 → 无外链校验 warning 兜底 |
| 页面定制 | 全部语义化 class（`rp-navbar/rp-toc/rp-fig/rp-callout`）+ `--rp-*` CSS 变量 + 品牌预设（smzy/jinyu/blank/default），一份自定义 CSS 即可整体换肤 |

## 5. 分阶段技术路线

可视化版本见 [reporter-roadmap.html](reporter-roadmap.html)。

### Phase 0 — 技术调研与选型 ✅（2026-10 完成）
- 产出：四方案六维对比矩阵；seqyuan/rst、Quarto 深度调研结论；纯 R 自建架构定稿。

### Phase 1 — 框架 + ChIP 试点 ✅（2026-10-29 完成，v0.1.0）
- 交付：reporter 包（47 导出函数）；ChIP 示范模块集 11 个（overview/qc/mapping/readsdist/peak/ip/similarity/diffpeak/enrich/motif/methods）；单文件内联管线；CLI。
- 验收（已达成）：testthat **73 项断言全绿**；e2e 断言 11 模块 0 错误、产物无外链；playwright **10 项 UI 交互零 console 报错**（截图 `examples/screenshots/`）；三份示例报告（blank/smzy/单分组）。

### Phase 2 — m6A 流程迁移（下一阶段）
- 范围：`m6A.Rmd` 1173 行按节拆解为 `R/modules.R` 内 m6A 模块集（QC/比对/Peak/差异/GO-KEGG/联合分析）；9 份变体收敛为 `required_dirs` + `when()` 声明；旧 Report.R 替换为 `run_report.R`。
- 验收标准：fixture 端到端测试全绿；同一份模板渲染 cq/jn/jy/noConjoint/nodiff 全部 5 类变体；图文编号连续无重复；CLI 退出码正确。
- 预估：模块契约已定型，主要为业务逻辑搬移，约 3-5 个工作日。

### Phase 3 — 其他流程铺开（RNA / CutTag / RIP 等）
- 范围：复用 ChIP/m6A 已验证模块（QC/比对/富集为高度共性），新流程只写差异模块；utils_RNA/utils_m6A 变体函数正式合并退役。
- 验收标准：每流程一组 fixture + e2e；`--modules <pipeline>` 全部可用；示例报告归档入 `examples/`。

### Phase 4 — 增强特性（按需排期）
- 暗色主题（`--rp-*` 变量体系已预留）；
- 大报告模式优化（`standalone=FALSE` + 懒加载，数百图场景）；
- 结果目录 schema 自动发现增强（进一步减少模块内硬编码路径）；
- Git 仓库化（代码/文档/配置模板入库，数据不入库）；
- 可选：reporter_theme 在线预览页（bs_themer）。

## 6. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 流水线输出目录结构变更导致模块门控失效 | 报告缺章 | `required_dirs` 集中声明 + `$skipped` 附原因显式呈现；Phase 4 schema 化 |
| 单文件体积随图片数增长（base64 +33%） | 客户端打开慢 | 已提供 `standalone=FALSE`；图先行压缩规范 |
| bslib/Bootstrap 升级改变默认样式 | 视觉回归 | 样式全走自有 CSS 变量；示例报告 + 截图作为视觉回归基线 |
| 模块作者绕过 ctx 读全局变量 | 可测性退化 | 代码评审约定 + e2e fixture 断言（模块在干净环境渲染） |
| reactable 大表内存占用 | 渲染变慢 | 默认分页 + 截断策略已内置；必要时静态表退化 |

# 网页报告设计调研：去"AI 化"的专业报告模板参照

> 2026-10-29 · 面向 reporter 报告视觉改版的设计调研
> 结论先行：**专业感来自克制**——低饱和灰阶 + 单一强调色 + 高信息密度 + 印刷排版细节；"AI 化"观感来自装饰堆砌（渐变、玻璃拟态、徽章、动效）。

---

## 1. 为什么现在的报告显得"AI 化"

2025 年起社区把这类一眼可辨的生成式界面称为 **"AI slop" design**。Cursor 设计负责人 Ryo Lu 在 Y Combinator Design Review 中的批判被广泛引用；Tailwind 作者 Adam Wathan 甚至公开道歉——Tailwind UI 五年前全面使用 `bg-indigo-500`，导致"地球上所有 AI 生成的界面都变成了紫色"。被点名的特征：

| AI 化特征 | 我们的报告里有没有 |
|---|---|
| 紫色/蓝紫渐变（hero 区、按钮、封面） | ⚠️ 有——封面渐变背景 |
| 玻璃拟态（毛玻璃卡片、backdrop-blur） | ⚠️ 有——导航栏 backdrop-filter |
| 圆角卡片 + 大阴影 + hover 上浮动效堆砌 | ⚠️ 有——所有内容块都是卡片 |
| 徽章/胶囊标签滥用 | ⚠️ 有——Figure N / Table N 徽章、项目编号徽章 |
| 滚动淡入、跟随光标等装饰性动效 | 部分 |
| 千篇一律的 Inter/系统无衬线 + 均匀圆角 | ⚠️ 是 |
| "每段内容都包一个卡片"的同构布局 | ⚠️ 是 |

**核心问题不是丑，而是"无主见"**：视觉决策均来自训练数据均值，而不是"报告需要让读者相信数据"这一目标。

## 2. 生信业内标杆（同行怎么做的）

### 2.1 MultiQC —— 生信 HTML 报告的事实标准
- **白底、零渐变、零阴影装饰**；整份报告只有 1 个 teal 强调色；
- 工具栏极简：搜索框 + 折叠按钮，其余全是内容；
- 信息密度高：样本 × 指标的大表格是主角，图表扁平无描边装饰；
- 分区靠**锚点导航 + 细分割线**，不靠卡片包裹。
- 可借鉴：**"内容即界面"**——装饰元素几乎为零，读者直接面对数据。

### 2.2 10x Genomics web_summary.html —— 单细胞报告行业标准
- 顶部 4 个 **KPI 大数字卡**（Estimated Cells / Reads / Q30 / Mapping），一眼读完实验质量；
- 每个指标卡**自带语义色边框**：绿色=正常、黄色=警告、红色=异常，并配一行解释文字；
- 单列纵向布局，无侧栏；sticky 顶栏只有样本名 + 版本；
- 每个指标旁一个 "?" 图标，悬停弹出**指标定义与阈值说明**——"解读内置在指标旁"而非集中成文字段落；
- 异常时页面顶部出现 alert 条（对应我们的 callout）。
- 可借鉴：**KPI 优先 + 语义色即判断**；阈值解释就近放置。

### 2.3 Illumina DRAGEN Reports —— 临床级克制
- Tab 分区（QC / Mapping / Variant…），每区是 dashboard 化的指标表 + 图；
- 配色只有品牌蓝 + 灰阶 + 红黄绿语义色；字号小、行距紧、表格斑马纹极淡；
- 大量使用**纯表格而非卡片**呈现指标，附参考范围列。
- 可借鉴：**表格是报告的主角**；参考范围/阈值列直接进表。

### 2.4 nf-core —— 统一品牌模板
- 全部子流程报告共用一套模板：白色 hero（仅品牌绿 1 处）、等宽字体代码块、简单锚点目录；
- "Report" 本身页面元素极少，靠 nav + 内容。

## 3. 跨行业参照（其他行业怎么排"报告"）

| 行业 | 代表 | 可迁移的设计要素 |
|---|---|---|
| 金融研究报告 | Morningstar、上市公司年报（annualreports.com 收录的壳版） | 衬线大标题 + 细规则线分区 + 页眉页脚页码 + 数字等宽排版（tabular-nums）+ 大量留白 |
| 咨询交付件 | McKinsey/BCG 图表页 | **一图一论点**：每张图标题即结论（"Peak 数随测序深度饱和"），图下小字注数据来源 |
| 开发者文档 | Stripe Docs、Linear、Vercel | 低饱和灰阶 + 单强调色；字重对比（600 标题/400 正文）代替颜色对比；侧栏极窄、无边框 |
| 笔记/知识库 | Notion export | 内容宽度 ~720px 居中、无卡片、标题层级靠字号而非色块 |
| BI 仪表盘 | Tableau/Looker 白底模板 | 指标行（metric row）+ 网格对齐，禁止装饰图形 |

## 4. 去AI化的十条设计原则（改版依据）

1. **一个强调色就够**：主色只用于链接、当前高亮、主按钮；其余全部灰阶。
2. **语义色只表达状态**：红黄绿只出现在质量判定/告警，不做装饰。
3. **去渐变、去玻璃、去阴影堆砌**：分区改用留白 + 1px 细规则线。
4. **卡片只留给"需要边界的东西"**：图表/表格直接放在版面上，不包壳。
5. **数字要用等宽数字**（`font-variant-numeric: tabular-nums`），大号 KPI + 小标签。
6. **图注即结论**：Figure 标题写成陈述句，编号弱化为前缀而非徽章。
7. **排版印刷化**：页眉（项目号/日期）、页脚（公司/免责/页码感）、标题层级用字重与字号。
8. **密度即专业**：表格紧凑（行高 ~1.4）、字号 13-15px、内容列宽 ~860px。
9. **动效只保留功能性的**：TOC 高亮过渡可以有；hover 上浮、淡入删掉。
10. **中英文混排规范**：中文黑体（Noto Sans SC/思源）+ 数字与西文用同族字体，标点细节统一。

## 5. reporter 改版方案（对照现状逐条）

| 现状（v0.1.0） | 改版方向（v0.2 视觉稿） |
|---|---|
| 封面柔和渐变背景 + 大标题 | 白底封面：细顶规则线 + 项目名小字 + 加粗大标题 + 生成日期；仿年报扉页 |
| 导航栏毛玻璃 + 阴影 | 纯白吸顶栏 + 1px 底边线，去掉 backdrop-filter |
| 每个小节一张圆角卡片 + hover 上浮 | 小节 = 标题 + 2px 主色短下划线 + 内容直排版面；卡片仅保留画廊/错误占位 |
| Figure N / Table N 徽章胶囊 | 灰色小号前缀文字 `Figure 3 ·` + 陈述句图注（结论式标题） |
| 项目编号/物种徽章 | 导航栏中部改为灰字文本 `72407172801 · Homo_sapiens (GRCh38)` |
| QC 结论集中在 callout | 仿 10x：模块首行 **KPI 指标行**（3-6 个大数字，语义色边），callout 仅保留 warning/danger |
| 内容区 950px、行距宽松 | 内容列 860px、表格行高 1.4、字号 13.5px 基准 |
| TOC 高亮色条 | 保留（功能性），但底色渐变改纯色 |
| 字体：系统栈 | `Noto Sans SC, PingFang SC, Microsoft YaHei + tabular-nums`；标题 600/700 字重对比 |

实施代价评估：全部通过 `inst/assets/reporter.css` 变量与布局调整 + `R/layout.R` 封面/KPI 原语改造实现，**不动模块契约与模块代码**——这正是分层架构的红利。建议以"新皮肤"方式并行开发（如 `reporter_theme(style = "v2")` 或独立 CSS 文件），与 v0.1.0 视觉对照验收后再切换默认。

> **落地状态（2026-10-29）**：v2 已实现为 `reporter_theme(style = "v2")`——`body.rp-style-v2` 作用域 CSS 覆盖 + 新增 `kpi()`/`kpi_row()` 原语（QC/Mapping 模块已接入语义色 KPI 行）。示例：`examples/chip_demo_v2.html`；新旧对比截图：`examples/screenshots/v2-compare-classic.png` vs `v2-compare-editorial.png`。默认仍为 classic，验收后切换。

# reporter 技术文档

> 版本 0.1.0 · 2026-10-29 · 面向包维护者与模块开发者

## 1. 设计总览

`reporter` 放弃「knit 一个巨型 Rmd」的文档驱动模式，改为**纯函数式内容组装**：

- **模块** = 普通 R 函数：输入报告上下文 `ctx`，输出 `htmltools::tagList`。
- **框架**负责其余一切：目录门控、异常降级、图/表编号、页面骨架、主题编译、单文件内联。
- **零外部运行时**：渲染路径不依赖 Quarto CLI、Node、pandoc（base64/内联全部自研）。

技术选型依据（2026-10 调研）：Quarto 模块化最强但需 150MB 非 R 二进制且服务器未装；
seqyuan/rst 是 TypeScript 的 reStructuredText 渲染引擎（非 R 包），需在流水线维护
Node 运行时；两者均排除，仅吸收其「模板/数据分离、结果目录自动发现、单文件交付」理念。

分层架构与渲染数据流见 `reporter-architecture.html` / `reporter-dataflow.html`
（archify 生成，内置主题切换与 PNG/SVG 导出；布局 JSON 同目录，可修改重渲染）。

## 2. 包内分层

| 层 | 文件 | 职责 |

## 3. 渲染管线（`render_report` 内部顺序）

1. **门控**：每个模块先过 `required_dirs`（相对 `ctx$meta$result_path` 的目录必须
   全部存在）与 `when(ctx)` 谓词；不满足 → 记入 `$skipped`（附原因），不渲染。
2. **隔离渲染**：`tryCatch` 内调用 `mod$render(ctx)`；成功 → tagList；失败 →
   `rp_error_block()`（报告内 danger 提示框，含 conditionMessage）并记入 `$errors`。
   任何单模块失败都不会中断整份报告。
3. **TOC 分组**：`ctx$subsection()` 在渲染期间把 `{module, title, id}` 写入 ctx
   注册表；渲染后按模块分组生成两级侧栏目录。
4. **骨架组装**：`rp_page()` = head（charset + bslib 编译依赖 + reporter.css/js）
   + 固定顶栏 + 侧栏 TOC + 封面 + 各模块 section + 页脚。
5. **落盘**：`standalone=TRUE`（默认）→ `htmltools::save_html(page, tmp, libdir="lib")`
   → `inline_html()` 内联 → 单文件落盘 → 删临时目录；`standalone=FALSE` →
   HTML + `report_assets/` 目录（大报告加载更快）。
6. **返回值**：`reporter_render` 对象（`output / errors / skipped / modules / counters / size`）。

### 3.1 单文件内联（`R/inline.R`）

- 图片：`figure()/gallery()` 生成时即 `xfun::base64_uri()` 编码（O(n) 一次读盘），
  不做事后正则替换，规避性能与遗漏风险。
- `<script src="lib/...">` → 内联 `<script>`；内容经 `rp_escape_inline_js()`
  （`</` → `<\/`）防止提前闭合标签，并剔除 sourceMappingURL 注释。
- `<link href="lib/...">` → 内联 `<style>`；CSS 内部 `url(...)`（字体等）相对其
  所在目录再次 base64 编码（`rp_inline_css_urls`）。
- 批量替换基于 `gregexpr + regmatches<-`（`rp_replace_matches`），一次替换全部匹配。
- **自包含校验**：收尾扫描 `(src|href)="lib/`，残留即 warning——单文件构建不合格
  不可能静默通过（e2e 测试有对应断言）。

### 3.2 编号器

`ctx` 内私有环境维护 fig/tbl 计数器，`ctx$figure()/ctx$data_table()/ctx$gallery()`
调用时自增，按 `caption_lang` 产出 "Figure N / Table N"（en）或 "图 N / 表 N"（zh）。
彻底取代旧 `tablenum=tablenum+1` 全局计数器——模块顺序变化不再影响编号。

## 4. 模块开发规范

1. 一个模块一个 `module()` 调用，放在 `R/modules-<pipeline>.R`；同时提供
   `xxx_report_modules(show_number = 10L)` 汇总函数。
2. **只通过 ctx 取数**：`ctx$meta`、`ctx$find()`；禁止读全局变量。
3. 输出必须是 tagList/HTML 块；长表格用 `ctx$data_table()`（reactable 交互），
   补充解释用 `table_explain(sheet)`（读 `inst/extdata/TableExplain.xlsx`）。
4. 缺结果时返回 `empty_block()`，不要静默空白。
5. `required_dirs` 必须与流水线实际输出目录一致（ChIP 布局见 `?chip_report_modules`）。
6. 模块内**绝不写结果目录**（保证渲染可重复）；确需写盘须显式路径参数。

### 4.1 新流程接入（以 m6A 为例）

1. 复制 `R/modules.R` 中最接近的模块改写业务逻辑，保持
   `function(ctx) -> tagList` 签名（模块库按流程分节，新流程新增一节）。
2. 实现并加入 `m6a_report_modules()`。
3. `R/cli.R` 的 `--modules` 开关加一项。
4. 在 `tests/testthat/helper-fixture.R` 增加该流程合成 fixture +
   `test-modules-m6a.R` 端到端用例（断言：模块渲染、编号顺序、无外链）。
5. 逐节从旧 `m6A.Rmd` 迁移，每节一个 subsection——旧文件按节退役，不再整份复制。

## 5. 错误处理语义（修复旧缺陷）

| 场景 | 行为 |
|---|---|
| 模块渲染抛错 | 该模块降级为报告内 danger 占位（含错误信息），其余模块照常 |
| 全部模块失败/被跳过 | `render_report()` 直接 `stop()`（"no module was rendered"） |
| 单文件内联后仍有外链 | warning 提示残留引用列表（构建不合格不可能静默） |
| CLI 任一模块失败 | 退出码 1；参数/环境错误退出码 2 —— 修复旧 Report.R 吞错仍返回成功 |
| `only=` 参数 | 只渲染指定模块 id —— 调试单个模块的快捷通道 |

## 6. 前端实现（`inst/assets/`）

- `reporter.css`：全部颜色走 `--rp-*` CSS 变量（bslib 编译注入），语义化 class；
  打印媒体自动隐藏导航/侧栏；≥1080px 桌面优先，窄屏收起侧栏。
- `reporter.js`（零 jQuery）：
  - 滚动同步：scroll 监听（rAF 节流）计算当前 section，高亮侧栏对应链接并自动滚动目录；
  - 画廊：pane 切换、样本列表点击、搜索过滤、左右方向键；
  - 灯箱：点击报告图放大 + Download（data URI 直接另存）+ Esc 关闭；
  - 侧栏折叠按钮，状态存 sessionStorage。

## 7. 性能与已知限制

- 单文件体积 ≈ Bootstrap+reactable 运行时（约 1MB）+ 图片 base64（约 +33%）。
  数百张大图场景建议 `standalone=FALSE`。
- `figure()` 逐张编码、即编即弃，不缓存全部 data URI 于内存。
- bslib 预设（bootswatch 主题）会附带 Google 字体依赖并被内联，显著增大体积——
  默认 preset 已避开，自定义 `bslib_preset` 时注意。
- HOMER knownResults.html 以 iframe `srcdoc` 方式嵌入（本地 `src` 会破坏自包含），
  嵌入前剥离绝对路径且不回写源文件。
- `plotly` 转换为 Suggests：`load_plot_objects()` 仅在安装了 plotly 时交互化 ggplot。
- OXM 包协作：`custome_theme_bw()`/`get_cols()` 可继续用于模块内绘图；
  OXM 的 `Reporter.R` 属旧式 knitr 拼接，不与 reporter 混用。

## 8. 测试与质量

- `tests/testthat/`：73 项断言全绿 —— context/编号器、原语、数据读取、
  内联无外链、e2e（11 模块 0 错误；type=0 自动跳过 diff/enrich/motif）、多文件模式。
- UI 证据：`examples/screenshots/`（导航栏、TOC 同步高亮、reactable 表格、
  画廊切换/搜索、灯箱、侧栏折叠、smzy 皮肤、单分组报告），浏览器 console 零报错。
- 包约定：全量 roxygen 文档、显式 `@importFrom`、无 `library()`、无 `:::`、
  无全局 `install.packages()`；`.Rprofile`/`env.sh` 仅前置私有库，不改系统配置。

## 附录：reporter 与 Rmd 渲染逻辑对比

两个体系解决同一个问题（结果目录 → 交付报告），但控制流完全倒置：

```
旧 Rmd 方案（文档驱动）                     reporter（代码驱动）
─────────────────────────                  ─────────────────────────
Report.R                                   create_report(ctx)
  ├─ optparse 解析参数                       ├─ ctx = report_context(...)     ← 状态唯一载体
  ├─ 参数写入 globalenv()      ══════▶       ├─ add_module(mod_a(), mod_b())  ← 模块=函数，无全局状态
  └─ rmarkdown::render(main.Rmd)             └─ render_report(report)
        │                                          │
  main.Rmd（模板）                            逐模块：
  ├─ YAML 头（主题/TOC/页脚）        ══════▶  theme 对象（bslib + --rp-* 变量）
  ├─ res_tree_dt 按目录存在性选 child ══════▶  module(required_dirs=, when=) 声明式门控
  ├─ loadRmd2(child1, child2, child3) ══════▶  tryCatch(mod$render(ctx)) 隔离渲染
  │    └─ child.Rmd 混合 文字+代码+HTML       │      └─ 失败→错误占位，不中断
  │        knit_child → 同一 knit 环境       │
  ├─ knitr 顺序求值：                         └─ 纯函数求值：
  │    `r tablenum=tablenum+1` 全局计数器     │     ctx$figure()/data_table() 内计数器
  │    表格: reactable() 直接打印             │     table_block()/figure_block() 原语
  │    图片: knitr::include_graphics()       │     figure() 生成时即 base64 内联
  └─ pandoc: Rmd → md → HTML                 └─ htmltools: tagList → save_html
       └─ self_contained 由 pandoc 打包              └─ inline_html() 自研内联+无外链校验
```

| 维度 | 旧 Rmd | reporter |
|---|---|---|
| 状态传递 | globalenv()（Report.R 写、Rmd 读、child 共享） | ctx 环境（引用语义，一处定义，静态可查） |
| 分支复用 | 整份复制 Rmd（22 份变体） | `required_dirs` + `when()` 声明，一份模板 |
| 章节调试 | 整份重 knit | `only = c("qc")` 单模块；testthat 直接断言返回值 |
| 失败语义 | knit 一处报错全文中断；Report.R 吞错 | 模块级降级占位 + 退出码 0/1/2 |
| 交付 | pandoc self_contained（依赖 pandoc） | 自研内联（base64+CSS/JS fold-in+无外链校验），零外部运行时 |
| 表格解释 | 每表手动 `addexplain(sheet)` | `ctx$data_table()` 自动查注册表挂载 |
| 参考文献 | pandoc + ref.bib + csl | `mod_references()` 纯 R 解析 .bib |
| 样式 | rmdformats 主题 + custom.css hack | bs_theme + `--rp-*` 变量 + classic/v2 皮肤 |

**一句话**：Rmd 的执行单位是"文档"（knit 时才把数据灌进模板，错误定位在渲染末期）；
reporter 的执行单位是"函数"（模块在 R 会话里直接求值成 HTML 片段，装配与渲染是
纯后处理）——所以调试从"改模板→重 knit→肉眼找错"变成"调用函数→断言输出"。
